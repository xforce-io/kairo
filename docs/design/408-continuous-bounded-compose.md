# #408 持续有界综合

状态：Approved（L1 核心取舍由用户在会话中以“go，端到端优化”批准；随后明确“开票并继续端到端”）

## 1 背景

[Issue #408](https://github.com/xforce-io/kairo/issues/408)。替代 #161/#386 中普通推进遇容量必须人工重综合的契约。保留正文上限、手改保护、溯源校验和失败保旧。

## 2 名词解释

沿用 [名词表](../glossary.md) 的 digest、fold、活 target、材料目录。N/A：无新增领域术语。

## 3 目标与非目标

普通推进自动去重、归并和压缩结论，持续接纳新材料；正文不是全部历史细节的副本。原始材料与 digest 不因压缩删除。

非目标：正文无损保留无限历史、语义真实性的确定性证明、向量库、新页面、新配置、改变显式全量 re-step 的含义、解决全量 re-step 的历史输入规模。

## 4 能力

普通增量正文目标 12,000 字符，完整文件硬上限 20,000 字符。目标预算用于指导模型，不再作为拒绝运行的阈值。每批新增 digest 预算 24,000 字符、最多 16 条；单条超预算 digest 独占一批，不截断材料。旧超长正文首次恢复允许读取原全文。

### 4.1 UI/UX

沿用 Topic 主按钮、运行日志、产物阅读面。容量失败属于普通运行可重试状态；日志显示综合批次和自动预算修订。成功阅读更新后的正文；空状态无新增材料不调用模型；失败保留最近成功批次的正文并给出匹配原因的恢复提示。手改与溯源等不可普通重试状态不显示“等待服务恢复”。不新增页面。

## 5 思路与折衷

常规输入为当前结论与有限新增 digest，自动整理而不累积全文。来源目录只提供当前正文引用的来源与本批来源；候选索引仅保留实际引用项，完整材料记录仍在既有 Ref/folded 中。

候选超过硬预算时最多修订一次，修订仍读取原输入，禁止外壳截断。失败后退出本次运行；下一次用户普通运行可重试。预算失败与服务失败保留触发语义。

保留普通增量骤缩保护，但比较基准最多按 20,000 字符计：自动压缩不能小于旧正文的一半（旧正文超长时最低 10,000），兼容从超长历史压缩到有界正文。这是粗粒度异常检测，不声称证明语义无损。显式全量 re-step 沿用原有例外。

放弃提高上限、仅凭新增体量预测是否允许处理、无限重试、每次自动读取全历史。单条 digest 不可分割和首次超长正文是输入预算的明确例外；不通过切断事实换取表面有界。

## 6 架构

规则层选择确定性批次、构造授读材料、生成和验证候选。引擎层持久化每批成功进度与失败状态。CLI/Web 共享可重试性判定，模型故障与人工保护分别提示。

主路径：普通推进 → 当前正文 + 本批新增 digest → 自动整理 → 必要时一次预算修订 → 预算/溯源/骤缩校验 → 写正文与本批 folded → 下一批 → 收敛。

失败路径：生成或校验失败 → 保留最近成功批次 → 记录具体原因 → 停止。后续普通运行仅继续未完成批次。手改检测先于容量恢复。

## 7 模块

ComposeRule 负责批次与候选保护；engine 负责容量原因的可重试性；CLI/Web 负责原因与恢复指引；文档、操作 skill 和测试同步新契约。

## 8 API/CLI

无新命令或参数。`kairo run` 可恢复 compose-migration-required 与 compose-over-budget；`step` 不主动清除上次失败。新产生超时统一 provider-failed，可普通重试。`re-step` 仍是显式全量重综合，并非日常容量恢复要求。

## 9 边界

仅 understanding.md 使用本票容量策略，自定义 target 保持兼容。正常无新增材料不调用模型；旧容量阻塞即使无新增 digest 也允许整理当前正文一次。容量恢复不得绕过手改。每批 folded 只含成功处理的 digest hash，不能提前登记后续批次。

## 10 迁移/兼容/回滚

无新状态文件格式。旧容量原因由普通 run 清除并保留重试触发标记；超长 leftover compose-degraded 沿用既有观察升迁，再进入容量恢复。旧文档不批量扫描改写。回滚代码后正文和 folded 仍可读，但旧容量门禁可能重新生效。显式 re-step / materials-changed 继续按全量语义处理，失败保留原版。

## 11 测试计划

E2E：S1 连续 5 轮普通 CLI 推进，累计材料 >20k，正文与关键事实来源可判；S2 至少 3 批且第 2 批失败后恢复；S3 注入预算、来源、骤缩、手改、服务失败并检查保旧及提示；S4 旧阻塞恢复和无新增材料零调用。全部映射 `.agents/skills/verify-kairo-web/features/continuous-compose.md`。在 scratch 上使用确定性 provider，禁止现网 LLM Run；这些验证证明机制与契约，不把 stub 当真实模型语义质量证明。

Integration：普通运行的逐批账本、重试语义、跨 home 来源、来源索引裁剪、CLI/Web 状态一致性、现有知识提取与手改保护回归。

Unit：批次预算边界、来源引用、20k/20k+1 输出边界、最多一次修订、超长旧正文的骤缩阈值。

## 12 开放问题

真实模型的压缩语义质量仍需实际材料长期观察；不能用字符数或来源结构校验替代语义评估。不阻碍确定性容量与恢复契约的验证。
