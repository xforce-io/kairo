# #354 Topic 成员材料页内阅读

状态：Approved。L1 已获用户 `approve`；[批准提案](https://github.com/xforce-io/kairo/issues/354#issuecomment-5599751089)。

## 1 背景

[#354](https://github.com/xforce-io/kairo/issues/354) 要求 Topic 阅读不再依赖材料的存放位置；同时修复首次打开、刷新与同 id 不同 home 的选择歧义。

## 2 名词解释

沿用[名词表](../glossary.md)的 Topic、Ref、Ref 身份键和包含规则，无新术语。

## 3 目标与非目标

目标：三类来源均在当前 Topic 阅读；地址可恢复完整身份；空与不可用状态明确。非目标：迁移数据、修改成员规则、自动加工、改版独立 Ref/Timeline、扩展跨来源写操作。

## 4 能力

### 4.1 UI/UX

保留现有三栏。左侧按发生日展示成员，正文与元信息在点击后一起切换，顶部保留当前 Topic。选中态按完整身份唯一匹配。首次加载和刷新使用相同选择；失效地址不回退到其它正文。

空产物沿用尚无可读内容提示；材料失效、非成员或来源无效显示材料不可用，并提供返回 Topic 入口。切换失败清除之前的正文与元信息。有效成员仍可点击。

本地材料保留既有管理能力；跨来源材料展示标题、时间、形态、分享与阅读，管理入口使用已有独立 Ref 详情，不向当前 Topic 同 id 材料发送写请求。形态切换（包括图像、音频听读）留在当前阅读区。正文相对纪要链接也保留当前 Topic 与来源身份，并同步选择、元信息和地址。

## 5 思路与折衷

当前 Topic 是阅读上下文，home + id 是材料身份，两者分离。URL 承载选择，完整页与局部加载都验证成员与公开边界。放弃复制材料和浏览器私有存储状态，避免身份分叉与跨窗口不一致。保留旧本地无 home 地址，以兼容已有链接。

## 6 架构

分层：成员目录提供身份与包含规则；Web 选择层解析当前 Topic 与 Ref 身份并校验访问；现有形态读取层生成内容；模板提供正文、元信息及选择。

主路径：Topic 链接 → 完整身份匹配当前可读成员 → 原存放位置读取 → 当前 Topic 页内呈现。失败路径：无成员、无权限或材料消失 → 不读取其它同 id 材料 → 不可用状态；缺正文 → 空产物状态。文件形态请求重复校验，不依赖先前打开过详情。

## 7 模块

成员导航与 Web 选择解析、元信息/形态渲染、Topic 模板及既有测试。加工引擎和存储结构不变。

## 8 API/CLI

GET `/w/{topic}?ref={id}&home={home}` 恢复材料选择，`/topics/{topic}` 保留查询转发。home 省略表示当前 Topic；`global` 表示全局材料。其它 home 必须严格匹配成员来源，不做同 id 猜测。

GET `/w/{topic}/ref/{id}`、其 `/form/{key}` 与 `/file/{key}` 支持同一 home 参数。局部详情不可用时返回可替换旧正文的状态片段；公开模式保留 404 状态，并向局部加载返回可清除旧正文的通用不可用片段；形态/文件不存在或越权仍拒绝访问。所有路径与参数编码，公开模式同时校验当前 Topic 可见和材料实际身份已公开。独立 `/refs` 与 Timeline 契约保留。CLI N/A。

## 9 边界

同 id 不同 home 不合并；未显式 home 的旧地址只指当前 Topic 材料。无效来源、目录穿越、被移除成员不可读取。公开模式不得借同 id 本地已公开记录读取全局私有材料。不得将跨来源写操作送往当前 Topic。

## 10 迁移/兼容/回滚

不迁移数据。旧本地阅读地址兼容；独立 Ref 分享入口不变。部署目标为用户批准的本机 launchd `com.kairo.web`、8787，加载 `/Users/xupeng/dev/github/kairo/src`，数据根 `/Users/xupeng/kairo`。

发布顺序：独立 worktree 测试和评审通过 → PR 检查通过并合并 main → 主仓库快进到合并版本 → `launchctl kickstart -k gui/$(id -u)/com.kairo.web`。部署前记录主仓库 SHA 与 launchd 配置。健康验证包括服务状态、Topic 返回成功、真实浏览器切换两条用户材料及刷新恢复。失败时将服务加载的代码恢复到记录版本并重启、复验；保留失败提交和用户未跟踪文件，不回滚资料。

## 11 测试计划

E2E/S1：真实浏览器点击本地、全局和其它 Topic 材料，核对 Topic/正文/选中态；S2：刷新及新窗口打开，含同 id 不同 home；S3：打开无产物、失效与非成员，随后恢复有效材料，核对无残留。使用既有 ego-browser 进行浏览器验收。

Integration：TestClient 验证完整页与局部/形态/文件请求、编码、成员移除、公开权限、corpus、旧链接和分享身份；Unit：通过同一测试文件的参数矩阵验证身份解析边界，不增加镜像测试。全量 pytest 作为既有行为回归。
